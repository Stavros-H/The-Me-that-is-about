App Storage
Persistent contact data must be stored in Replit App Storage using this object path:
data/contactReceived.json
This JSON file stores all contact form submissions and their current status.

Contact Form Persistence
Use Replit App Storage so submissions persist across server restarts and deployments.
Do not use browser localStorage, an in-memory array, or the local server filesystem as the primary data store.
data/contactReceived.json must contain a valid JSON array.
If data/contactReceived.json does not exist, the server must initialize it as an empty array:
[]
Contact Submission Format
Each contact record must include:
id: Unique string
firstName: String
lastName: String
email: Valid email address
reason: Comment, Question, Partnership, Opportunity, or Other
message: Non-empty string
submittedAt: ISO 8601 timestamp
replied: Boolean, initially false
repliedAt: ISO 8601 timestamp or null, initially null
Example data structure:
[
  {
    "id": "unique-id",
    "firstName": "Jamie",
    "lastName": "Smith",
    "email": "jamie@example.com",
    "reason": "Question",
    "message": "I have a question about your project.",
    "submittedAt": "2026-08-25T18:30:00",
    "replied": false,
    "repliedAt": null
  }
]
Contact Form Acceptance Tests
A valid form submission returns HTTP 201.
The response contains the generated ID and submission timestamp.
data/contactReceived.json exists in App Storage after the first submission.
The file contains the submitted record as valid JSON.
Multiple submissions are added to the JSON array without deleting previous submissions.
Submissions remain available after restarting the server.
Invalid submissions return HTTP 400 and do not modify the JSON file.
A storage failure returns HTTP 500 and displays an error message in the user interface.
Public contact submission does not require an Admin password, email provider, database, or other external service.
Contact Form Implementation
Use one Express endpoint:
POST /api/contact
The endpoint must:
Receive the form data.
Validate the request.
Read data/contactReceived.json from App Storage.
Initialize the file to [] if it does not exist.
Generate a unique ID and submission timestamp.
Append the new submission.
Write the complete JSON array back to App Storage.
Return the saved record with HTTP 201.

Admin Page
The Admin page provides a simple dashboard for managing and analyzing contact form submissions.
Password Protection
Access to contact message data and Admin operations requires a password.
Store the Admin password using Replit Secrets.
The Admin password must not be written directly into HTML, CSS, client-side JavaScript, or other publicly accessible files.
Password verification must occur on the server.
A visitor who has not successfully authenticated cannot retrieve contact message data or perform Admin operations.
The Admin password must not be stored in browser localStorage.
Message Management
The Admin dashboard must:
Read message data from data/contactReceived.json.
Display all contact submissions.
Show newest messages first.
Display each message's:
Name
Email
Reason
Message
Date received
Reply status
Clearly identify messages as New or Replied.
Allow the Admin to filter messages by:
All
New
Replied
Mark as Replied
Each new message must include a Mark as Replied operation.
When selected:
Find the message using its unique id.
Change its replied value from false to true.
Save the current date and time to repliedAt.
Write the updated JSON array back to data/contactReceived.json.
Update the Admin dashboard to show the new status.
The operation must modify the stored JSON data. Changing only what appears on the screen does not meet the requirement.
Dashboard Summary Values
The Admin dashboard must automatically calculate and display:
Total Messages
New Messages
Replied Messages
Reply Rate
Reply Rate is calculated as:
Replied Messages ÷ Total Messages × 100
These values must be calculated from the current JSON data and may not be hard-coded.
Dashboard Chart
Include at least one chart showing:
Messages by Reason for Contact
The chart must:
Use the current contact submission data.
Display the number of messages in each Reason for Contact category.
Automatically update when the underlying data changes.
Include a clear title and category labels.
A JavaScript chart library such as Chart.js may be used.
Admin Implementation
The server must provide protected endpoints that allow the Admin dashboard to retrieve and update contact data.
At minimum, the application must support:
Admin password verification
Retrieving contact messages
Marking a message as replied
Suggested endpoints:
POST /api/admin/login
GET /api/admin/messages
PATCH /api/admin/messages/:id/replied
The endpoints for retrieving and modifying contact data must require successful Admin authentication.
Admin Acceptance Tests
An incorrect Admin password does not provide access to contact message data.
A correct Admin password provides access to the dashboard.
Contact messages are loaded from data/contactReceived.json.
Messages appear newest first.
All, New, and Replied filters display the correct messages.
Dashboard summary values match the stored JSON data.
The chart accurately represents the Reason for Contact values in the stored data.
Selecting Mark as Replied changes replied to true.
Selecting Mark as Replied adds a valid timestamp to repliedAt.
The updated reply status persists after refreshing the page or restarting the server.
An unauthenticated visitor cannot retrieve messages or perform the Mark as Replied operation.
